## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Stubbed Conversation lookup in test_skill_index_appended_to_prompt**

- **Found during:** Task 3.3 verification — broader test suite run after committing the run_task Conversation lookup wiring revealed `tests/unit/test_prompts.py::test_skill_index_appended_to_prompt` was now failing with `pydantic_core._pydantic_core.ValidationError: 1 validation error for StartWorkflowTool / conversation_id / Input should be a valid string [type=string_type, input_value=<MagicMock ...>]`.
- **Root cause:** The test uses a generic `MagicMock()` for the SQLAlchemy session. With my Task 3.3 change, run_task now calls `_session.query(Conversation).filter_by(...).one()` and threads `.id` into `StartWorkflowTool(conversation_id=...)`. Without an explicit stub, MagicMock auto-creates `.one().id` as another MagicMock instance (not a string), which the new `conversation_id: str` field on StartWorkflowTool rejects.
- **Fix:** Added a 7-line stub mirroring the pattern already in `tests/unit/test_agent_runner.py::test_run_task_injects_all_three_tools_for_handle_incoming_message`: `fake_conversation = MagicMock(); fake_conversation.id = "conv-stub-1"; query_mock = MagicMock(); query_mock.filter_by.return_value = query_mock; query_mock.one.return_value = fake_conversation; mock_session.query.return_value = query_mock`.
- **Files modified:** `tests/unit/test_prompts.py` (+10 LOC including the comment header).
- **Commit:** `759ca68`
- **Scope justification:** This is a Rule 1 fix because the test failure is directly caused by Task 3.3's source change. The plan's list of test sites to update did not include this test (only enumerated test_start_workflow_tool.py + test_workflow_runner.py + test_agent_runner.py). Stub-pattern was reused verbatim from the existing test — no new pattern introduced.
