<objective>
Eliminate the `send-notification` LLM agent. Replace it with a deterministic Python path inside `run_task`: read `SendNotificationInput`, call `send_message(parse_mode=None)`, return an artifact dict. No LLM, no tool loop, no MarkdownV2 escaping. This kills the agent that produced the infinite-loop bug captured in `infinite-loop-messages.log`.
</objective>

<context>
@.planning/phases/07.1-deterministic-agent-termination-make-termination-a-runtime-g/07.1-CONTEXT.md

The `send-notification` agent today (`agents.py:51-64`, `prompts/send-notification/V001.md`, `tools/send_notification.py`) wraps a pure `escape_markdown(text) → send_message(text)` operation in a `create_react_agent` loop. Because the model is the loop controller, after a successful side effect it can — and frequently does — choose to call the tool again.

After this plan, `send-notification` is a non-LLM RQ task type. The existing trailing `notify` workflow step in `add-recipe` (`workflows.py:159-166`) is unaffected — its input shape (`SendNotificationInput`) is unchanged.

Plain-text mode (`parse_mode=None`) means no escaping is required. Telegram renders any character literally. Bold/italic/lists are dropped from existing replies; this is acceptable per the design discussion.

Per `feedback_avoid_premature_abstraction.md`, do not introduce a generic "non-LLM task type" abstraction. Use a small inline `if/else` branch in `run_task`. We have one such task today; abstract once we have ≥3.
</context>

<task name="1: Branch run_task on send-notification">
**File:** `src/robotina/queue/jobs.py`

At the top of `run_task` after `task_type = job.meta.get("task_type")` is read and the workflow setup runs (`workflow_runner.on_step_start`), add a branch:

```python
if task_type == "send-notification":
    # Deterministic non-LLM delivery path (Phase 07.1 — see 07.1-CONTEXT.md).
    # send-notification has no business being an LLM agent: it's a pure delivery call.
    from robotina.gateway.send import send_message
    import asyncio
    try:
        result = asyncio.run(send_message(
            chat_id=task_input.chat_id,
            text=task_input.text,
            user_id=task_input.user_id,
            parse_mode=None,
        ))
        artifact = {"message_id": result.message_id}
        logger.info("send-notification delivered | chat_id=%s message_id=%s", task_input.chat_id, result.message_id)
        workflow_runner.on_step_complete(job.id, artifact, _session, _queue)
        return artifact
    except Exception:
        workflow_runner.on_step_failed(job.id, _session)
        raise
    finally:
        _session.close()
```

Keep the existing agent path for all other task types intact. The branch is mutually exclusive with the agent path — return early.

```python
if task_type == "send-notification":
    from robotina.agent.tools.send_notification import SendNotificationTool
    tools.append(SendNotificationTool(...))
```

This block is unreachable after the branch above — delete it.
