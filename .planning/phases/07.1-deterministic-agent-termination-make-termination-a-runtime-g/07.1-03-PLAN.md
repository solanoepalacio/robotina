<objective>
Make `QueueTool` and `StartWorkflowTool` return `Command(goto=END)` so the LangGraph agent state machine cannot loop after either tool succeeds. Termination becomes a runtime guarantee enforced by the engine, not a request encoded in prompt text.
</objective>

<context>
@.planning/phases/07.1-deterministic-agent-termination-make-termination-a-runtime-g/07.1-CONTEXT.md

LangGraph 1.x supports tools that return a `Command` instead of a plain string. When a tool returns `Command(goto=END, update={...})`, the graph routes to END immediately after the tool runs — the model is not invoked again. This is the canonical "this tool ends the run" pattern.

Plan 02 must already have landed: terminal `queue` would break the routing prompt's "queue ack then start-workflow" sequence. After Plan 02, the routing agent emits exactly ONE tool call per request. After this plan, the engine guarantees that one call is the only call.

The new `acknowledge-add-recipe` agent (introduced in Plan 02) only has `queue`; this plan makes its single tool call terminal too.

LangGraph 1.1.3 (per `pyproject.toml:19` and `uv.lock:583`) imports:
- `Command` → `from langgraph.types import Command`
- `END` → `from langgraph.graph import END`
- `InjectedToolCallId` → `from langchain_core.tools import InjectedToolCallId`
- `ToolMessage` → `from langchain_core.messages import ToolMessage`

If any import path differs at implementation time, follow the langgraph 1.1.3 source.
</context>

<task name="1: Make QueueTool terminal">
**File:** `src/robotina/agent/tools/queue.py`

Update `_run` (and `_arun`) to return `Command(goto=END)`:

```python
from typing import Annotated
from langchain_core.messages import ToolMessage
from langchain_core.tools import BaseTool, InjectedToolCallId
from langgraph.graph import END
from langgraph.types import Command


class QueueTool(BaseTool):
    name: str = "queue"
    description: str = (
        "Enqueue a send-notification task to deliver a reply to the user. "
        "Use this for direct replies (answers to questions) or for acknowledgment messages. "
        "Args: text (str) — the reply text to send to the user."
    )
    chat_id: str
    user_id: str
    platform: str

    def _run(self, text: str, tool_call_id: Annotated[str, InjectedToolCallId]) -> Command:
        from robotina.queue.task_types import SendNotificationInput

        task_input = SendNotificationInput(
            platform=self.platform,
            chat_id=self.chat_id,
            user_id=self.user_id,
            text=text,
        )
        q = Queue(
            "agent-tasks",
            connection=Redis.from_url(os.environ.get("REDIS_URL", "redis://localhost:6379")),
        )
        job = q.enqueue(
            "robotina.queue.jobs.run_task",
            task_input,
            result_ttl=-1,
            failure_ttl=-1,
            meta={"task_type": "send-notification"},
            at_front=True,
        )
        logger.info("queue tool | enqueued send-notification | job_id=%s", job.id)
        return Command(
            update={"messages": [ToolMessage(
                content=f"Reply queued. job_id={job.id}",
                tool_call_id=tool_call_id,
                name="queue",
            )]},
            goto=END,
        )

    async def _arun(self, text: str, tool_call_id: Annotated[str, InjectedToolCallId]) -> Command:
        return self._run(text, tool_call_id)
```

Notes:
- The description string drops the "do not call again" prompt-level hack — the engine guarantees it now.
- `at_front=True` is preserved (`feedback_queue_at_front.md`).

<task name="2: Make StartWorkflowTool terminal">
**File:** `src/robotina/agent/tools/start_workflow.py`

Apply the same pattern. Both happy and error paths return `Command(goto=END)` — we don't want the agent to loop on a failed workflow start either:

```python
def _run(
    self,
    workflow_type: str,
    shared_context: dict,
    tool_call_id: Annotated[str, InjectedToolCallId],
) -> Command:
    from redis import Redis
    from rq import Queue
    from robotina.db import SessionLocal
    from robotina.queue import workflow_runner

    shared_context.setdefault("reply_context", {
        "platform": self.platform,
        "chat_id": self.chat_id,
        "user_id": self.user_id,
    })
    shared_context.setdefault("household_id", self.household_id)
    household_id = shared_context.get("household_id", "")
    session = SessionLocal()
    try:
        queue = Queue("agent-tasks", connection=Redis.from_url(
            os.environ.get("REDIS_URL", "redis://localhost:6379")))
        workflow_run_id = workflow_runner.queue_workflow(
            workflow_type=workflow_type,
            shared_context=shared_context,
            household_id=household_id,
            queue=queue,
            session=session,
        )
        logger.info("queue-workflow tool | workflow_type=%s run_id=%s", workflow_type, workflow_run_id)
        content = f"Workflow started. workflow_run_id={workflow_run_id}"
    except Exception as exc:
        logger.error("start-workflow tool | workflow_type=%s error=%s", workflow_type, exc)
        content = f"Workflow start failed: {exc}"
    finally:
        session.close()

    return Command(
        update={"messages": [ToolMessage(
            content=content,
            tool_call_id=tool_call_id,
            name="start-workflow",
        )]},
        goto=END,
    )
```

Drop the "do not call it again" line from the tool description; replace with a one-liner stating the tool's effect.
