# Phase 07.1 Context — Deterministic Agent Termination

## Why this phase exists

Robotina's agent layer has a recurring duplicate-message bug and a (rare) infinite-loop bug. `infinite-loop-messages.log` (project root) captured a single `send-notification` RQ job (`c1d614ab-…`) that called its tool 24 times in ~3 minutes, sending duplicate Telegram messages each round. The model received `"Notification Successfully Delivered"` after every call and still emitted another tool call.

**Root cause:** termination is delegated to the LLM. `langgraph.prebuilt.create_react_agent` loops until the model emits an assistant message with no tool calls. With a small local model (`gpt-oss:20b` via Ollama) and a noisy reasoning trace, the "am I done?" decision is non-deterministic. Prompt-level "do not call this tool again" hacks in `queue.py:85-88`, `send_notification.py:38-43`, and `start_workflow.py:45-52` are not enforceable.

**Architectural fix (this phase):** make termination a runtime guarantee, not a prompt request:
1. Replace the `send-notification` agent with deterministic Python (plain text — no MarkdownV2). It's a pure transformation followed by an HTTP call; an LLM loop has no business there.
2. Move the workflow acknowledgment side effect out of the routing agent into a per-workflow ack agent (`acknowledge-add-recipe`), inserted as workflow step 1.
3. Make the routing agent's `queue` and `start-workflow` tools return `Command(goto=END)` so the LangGraph state machine cannot loop after either is called.

After this phase, every agent run that successfully emits a side-effecting tool call ends in exactly one round.

## Out of scope (deferred)

- Applying the terminal-tool pattern to `recipe-load` and `recipe-research-*`.
- Defense-in-depth `recursion_limit` ceilings.
- Generic acknowledgment-composition agent (per `feedback_avoid_premature_abstraction.md`, we use one per-workflow agent for now and refactor when ≥3 instances exist).
- Removing Path A direct-reply composition from the routing agent (tracked in `project_compose_agent_vision.md`).

## Success criteria

1. `send-notification` task type runs without invoking any LLM (no `LLM stream start` log line for it).
2. Routing agent emits exactly one tool call per request and terminates immediately after.
3. Each per-workflow ack agent emits exactly one `queue` tool call and terminates immediately after.
4. Sending the same Telegram message that historically caused duplicates produces exactly one Telegram message.
5. Existing `add-recipe` workflow runs end-to-end with: 1 ack message at the start (from new step 1) + final notification (from existing trailing `notify` step). No duplicates anywhere.
6. `uv run pytest` passes the full suite.
