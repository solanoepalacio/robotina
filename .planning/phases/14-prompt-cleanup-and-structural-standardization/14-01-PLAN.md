The standardized skeleton (use for this plan AND all subsequent prompt-bump plans 14-02 through 14-07):

```
# {Agent display name} — V{nnn}

## Role

{One paragraph: what this agent is and what it produces. No banner, no shouty caps.}

## Inputs

{Bullet list of what arrives in the user message: workflow shared_context fields, prior step outputs, raw text. Skip the section ONLY if the agent has no structured input beyond the user message text.}

## Tools

- `tool-name` — short description, when to call.
(If no tools: "This agent uses no tools — produces output directly from the user message.")

## Process

1. Numbered steps, single action each.
2. Reference tools by name where relevant.
3. Keep this section concrete and operational.

## Rules

- All user-facing content (queued replies, recipe text) is in Argentine / Latin American Spanish. Only this instructional prompt stays in English.
- {Any other constraints unique to this agent.}

## Output

{For agents WITH response_format_model: one or two sentences naming the Pydantic class in src/robotina/queue/task_types.py and pointing to it as the schema source of truth. Do NOT re-describe field names, types, or rules — they live on the Pydantic model.}

{For agents WITHOUT response_format_model (the two delivery agents — handle-incoming-message and acknowledge-add-recipe): describe the delivery side-effect (which tool call terminates the turn) instead of a schema.}
```

Override file convention (every prompt-bump plan in Phase 14 follows this):

- The three `overrides/*.json` files currently override `model_config` per agent. They MUST NOT carry a `prompt_path` key — the registry is the single source of truth for prompt paths.
- If an existing override block contains `prompt_path`, the prompt-bump plan removes it.
- If an override file lacks an entry for the agent (e.g., `recipe-load` is absent from anthropic.json today), the plan does NOT add one — model_config overrides are independent of prompt paths.

Behavioral content for the Robotina router (preserve verbatim from V002 — see V002.md @rules):
- Every turn MUST end in a tool call (`queue` or `start-workflow`).
- Routing question: "Does fulfilling this request require multiple sequential operations across more than one task type?"
- Plain assistant text is never delivered — always use `queue`.
- For `start-workflow`: do NOT additionally call `queue` in the same turn — the workflow's first step (acknowledge-add-recipe) handles user-facing acknowledgment.
- `household-manager-api` is an intermediate tool — does not terminate the turn.
- `reply_context` and `household_id` are injected automatically — only pass task-specific fields in `shared_context`.
