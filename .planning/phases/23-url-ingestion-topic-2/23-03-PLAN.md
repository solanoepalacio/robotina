Implement the deterministic `FetchAndScrapeTool` — the LangChain BaseTool that the `gather-from-url` agent uses. RecipeData (existing, in robotina.queue.task_types): `name` is the only required field; ingredients[] and steps[] are lists of dicts.

recipe-scrapers field map (RESEARCH.md Pattern 2):
- name ← scraper.title()
- description ← scraper.description()
- total_time / prep_time / cook_time ← scraper.{total,prep,cook}_time()
- servings_qty ← scraper.yields() (coerce string like "4 personas" to int via regex)
- source_url ← scraper.canonical_url() (fallback to fetched.final_url)
- ingredients ← [{"food_name": s} for s in scraper.ingredients()]
- steps ← [{"body": s} for s in scraper.instructions_list()]

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Untrusted HTML response → recipe_scrapers / trafilatura | Remote HTML reaches parsers |
| LLM tool args → FetchAndScrapeArgs | Untrusted url:str validated by safe_fetch |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-PARSER-CRASH | D | recipe_scrapers per-method | mitigate | Per-field try/except (Pitfall 7) — any per-method exception isolated; tool always returns a valid FetchAndScrapeResult |
| T-23-CONTENT-INJECTION | T | RecipeData fields populated from HTML | accept | Downstream agents already operate on LLM-emitted RecipeData; the field shape is enforced by RecipeData.model_validate; no SQL/HTML rendering risk in queue/dashboard (auto-escaped Jinja) |
| T-23-CTX-BLOAT | D | trafilatura output → LLM context | mitigate | html_text capped at 200_000 chars before placing in tool result (prevents token-cost blowup) |
| T-23-SAFE-FETCH-BYPASS | E | FetchAndScrapeTool._run | mitigate | safe_fetch errors re-raise (D-03); no try/except surrounding the safe_fetch call; step FAILED on any defense violation |
| T-23-LARGE-BODY-DECODE | D | content_bytes.decode("utf-8") | accept | safe_fetch already capped body size at 5 MB; UTF-8 decode of 5 MB is fast (~tens of ms) and bounded |
</threat_model>
