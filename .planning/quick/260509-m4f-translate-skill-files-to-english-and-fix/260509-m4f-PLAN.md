<translation_rule>
The decisive rule for every edit in this plan:

- Instruction text (headings, prose telling the model what to do, bullet points describing process) → **English**.
- Example **values** the model is supposed to mimic in its own output (search-query phrases like `"pastel de calabaza casero"`, recipe titles like `"Tortilla espanola"`, food names like `"cebolla"`, `"aceite de oliva"`, unit names like `"unidad"`, `"cucharada"`, ingredient notes like `"picada finamente"`, `"cortadas finas"`, recipe descriptions, instruction-step bodies like `"Batir los huevos con sal."`) → **stay in Spanish**.
- The household-manager API is documented in English already; do not "re-translate" Spanish *data values* (food names, unit names, recipe names) that appear inside JSON examples — those are domain data, not instructions.
- File names, JSON keys, code-block identifiers, HTTP verbs/paths, MIME types → unchanged.
- The "Data language" section in `shared.md` (paragraph that says all household-manager data is stored in Spanish) → unchanged; it is already in English and is correct.

Heuristic when ambiguous: if the sentence tells the model *what to do*, it is an instruction → English. If the sentence is *an example of what the model should produce*, it stays Spanish.
</translation_rule>

<canonical_null_rule>
The exact paragraph (or a near-verbatim variant — same content, same shape) to insert in every skill file that documents a JSON output. Word it once and reuse it; do not invent variations:

> **JSON output rules.** Use the JSON literal `null` for missing optional fields — never the Python value `None`, never the bare word `none`, never an empty string in place of `null`. Booleans are `true` and `false`, lowercase. Numeric fields are bare numbers, never quoted. Do not omit optional fields when you have decided their value is "missing" — emit them with `null`.

Place it once per file, in the "Output format" / response section, immediately above or below the JSON example. For `recipe-research/metadata.md`, keep the additional, file-specific rule that **time fields (`prep_time`, `cook_time`, `total_time`) must always be numeric** — restate it in English right after the canonical paragraph; do not let it contradict the canonical rule (the time-field rule is a *narrower* constraint on three specific fields, not a global contradiction).
</canonical_null_rule>
