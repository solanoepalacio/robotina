# Quick Task 260509-m4f — Detailed Brief

**Goal:** Align all skill files (`src/robotina/agent/skills/`) with the project rule that *prompts/instructions are in English; only user-facing outputs are Spanish*. Translate Spanish instruction text to English and fix the contradictory null-handling guidance in `gather.md`.

## Background (why)

The project rule (per CLAUDE.md and standing memory) is: **system prompts and instructions in English; outputs to the user in Argentine Spanish**. The skill files currently violate this — many contain Spanish instruction text (e.g., `# Gather: Busqueda de recetas en la web`, `Los campos faltantes se omiten`).

Worse, `recipe-research/gather.md` contains the contradictory instruction `"Los campos faltantes se omiten (no uses null)"` while sibling skill files (`ingredients.md`, `instructions.md`, `metadata.md`) show JSON examples *with* `null` values. A small model whipsawed between "don't use null" and "use null" will sometimes generate creative output like `none` — which is exactly the bug we hit.

## Scope

Edit every `.md` file under:

- `src/robotina/agent/skills/recipe-research/`
- `src/robotina/agent/skills/household-manager/`

For each file:

### 1. Translate instruction text to English

- Section headings, prose instructions, bullet points → English.
- Keep file names, JSON keys, code blocks, and **example values that the model is supposed to mimic in Spanish** (e.g., search-query examples like `"pastel de calabaza casero"`, recipe titles, ingredient names) — those are *content samples*, not instructions, and they need to stay Spanish so the model produces Spanish output.
- When in doubt: if the text instructs the model what to do → translate to English. If the text is an example of model output → keep in Spanish.

### 2. Fix the null-handling contradiction in `recipe-research/gather.md`

The current guidance (paraphrased): "missing fields are omitted, do not use null." Replace with consistent guidance aligned with the rest of the skill files: **use JSON `null` for missing optional fields. Never use Python `None` or the bare word `none`. Use `true`/`false` (lowercase) for booleans, never `True`/`False`.**

Apply the same null-handling rule (one short paragraph) to **every** skill file that documents JSON output, so the guidance is uniform across the family.

### 3. Make null usage in JSON examples consistent

Audit JSON examples across all skill files. Anywhere an optional field is shown without a value, ensure the example uses `null` (not omitted, not `None`, not blank). The model copies these examples; consistency matters.
