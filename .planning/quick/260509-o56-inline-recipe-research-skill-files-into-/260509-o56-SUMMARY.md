# Quick Task 260509-o56: Inline recipe-research skill files into 4 sub-agent prompts — Summary

Inlined each of 5 recipe-research skill sub-files into its 1:1 sub-agent prompt, then deleted the skill directory and set `skills=[]` on the 4 recipe-research-* agents in the registry — collapsing a per-agent tool round-trip into a single self-contained prompt without changing the agent contract.

## What Changed

### Task 1 — Inline skill content into the four sub-agent prompts (commit `6e30bb7`)

Rewrote all four `src/robotina/agent/prompts/recipe-research-{gather,instructions,ingredients,metadata}/V001.md` files. Each rewritten prompt is now fully self-contained — an agent reading only the prompt has everything it needs.

For each prompt:

- Removed the `read-skill` line from the "Available tools" section.
- Removed step 1 ("Use `read-skill` with `recipe-research/<step>.md`...") from the Process section, renumbering the remaining steps.
- Inlined the full per-step procedural content from the matching skill sub-file.
- Inlined the full "Output format" JSON example block verbatim.
- Inlined the JSON output rules paragraph (`null` literal, lowercase booleans, bare numbers, emit `null` rather than omit).
- Carried over the Argentine / Latin-American Spanish register notes from `index.md`.

Per-prompt specifics:

- **gather**: lists `web-search` only as available tool; merged build-queries / search / extract / error-handling steps and Argentine-Spanish search-query examples; preserved the existing CORRECT/INCORRECT bare-array guard (`{"recipes": [...]}` vs `[...]`); preserved the "at least 1 usable recipe to succeed" rule.
- **instructions**: replaced "Available tools" with a one-line note that no tools are used (the agent has none after `skills=[]`); merged majority-wins consensus heuristic including the 6/10 + tie-break examples; merged Argentine kitchen vocabulary guidance.
- **ingredients**: lists `household-manager-api` only; merged extract / verify-via-`GET /api/foods?name=` / substitute-from-other-recipes / "do not create new foods" steps.
- **metadata**: replaced "Available tools" with the same one-line "no tools" note; merged time/servings estimation including the default-of-4 fallback and the narrower "time fields are NEVER null" constraint.

### Task 2 — Drop the skill bundle, set `skills=[]`, update tests (commit `c018f0d`)

- **`src/robotina/agent/agents.py`**: 4 recipe-research-* `AgentConfig`s now have `skills=[]` (was `skills=["recipe-research"]`). `handle-incoming-message` and `recipe-load` still use `skills=["household-manager"]` — untouched. Comments on the `tools=[]` lines for `instructions` and `metadata` updated from "only read-skill (generic injection)" to "no tools — produces JSON directly from user message" to reflect the new reality.
- **Deleted `src/robotina/agent/skills/recipe-research/`** (5 files: index.md, gather.md, instructions.md, ingredients.md, metadata.md). `src/robotina/agent/skills/household-manager/` remains intact (8 files unchanged).

Every other test in the file (10 passing tests including the 7 ReadSkillTool/SkillSet generic tests, 2 household-manager shared.md guard tests, and the build_read_skill_tool test) is untouched.
- **`tests/unit/test_agents_registry.py`**: the 4 `test_recipe_research_*_registered` tests now assert `config.skills == []`. Every other field assertion (model_config, prompt_path, api_key_env) is unchanged.
