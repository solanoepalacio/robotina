**B. tests/unit/test_gateway_boot.py (test_main_exits_on_missing_household_id):**
The test relies on a clean subprocess env, but `_base_env()` does not strip `HOUSEHOLD_ID` from the parent process env — `_base_env` only forwards `PATH` etc., so the subprocess SHOULD see no HOUSEHOLD_ID. However the failure is from `.env`-file loading inside the subprocess (python-dotenv auto-load). Fix: in the subprocess env, set `HOUSEHOLD_ID=""` is NOT acceptable (that's the empty-id test). Instead, set an env var that disables dotenv auto-load OR change the subprocess command to bypass dotenv.

Concretely: change `_run_gateway_main` so the subprocess explicitly disables dotenv loading. The simplest fix is to add `DOTENV_PATH=/dev/null` to the env dict and ensure the subprocess uses `cwd=tmp_path` (passed via a temp dir fixture) so it cannot find a sibling `.env`. Use `tmp_path` fixture: change `test_main_exits_on_missing_household_id(tmp_path)` and pass `cwd=str(tmp_path)` into `subprocess.run` inside `_run_gateway_main` (extend the helper to accept an optional `cwd` kwarg, default `None`).

If after applying the `cwd=tmp_path` fix the test still fails (dotenv may walk up), additionally set env `PYTHONDONTWRITEBYTECODE=1` and pass `env={..., "HOUSEHOLD_ID": ""}` is wrong — must remain ABSENT. The `cwd` change alone should suffice because python-dotenv's default `load_dotenv()` only searches CWD upward; pointing CWD at an isolated tmp dir prevents discovery.

Apply the same `cwd=tmp_path` treatment to `test_main_exits_on_empty_household_id` and `test_main_exits_on_whitespace_household_id` for consistency (they currently pass because the env var override wins, but the dotenv leak makes them fragile).
