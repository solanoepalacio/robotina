# Quick Task 260509-m46: JSON-Literal Guidance in Dict-Arg Tool Descriptions Summary

Appended explicit JSON-literal guidance (`null` not `None`/`none`, `true`/`false` not `True`/`False`, double-quoted strings, plus a concrete contrast example) to the `description=` attribute of `HouseholdManagerApiTool` and `StartWorkflowTool` — addressing the root cause of a workflow failure where the model emitted Python literals on a tool call and tripped Ollama's tool-call validator.

## What Changed

### `src/robotina/agent/tools/household_manager_api.py`

Appended to the existing `description = (...)` literal, after the existing `query (dict | None) — URL query parameters for filtering/pagination.` line. Verbatim new segment (3 implicitly concatenated string literals):

```python
"Arguments are passed as JSON. Use JSON literals: null (not None or none), "
"true/false (not True/False). Strings must use double quotes. "
"Example: {\"query\": null}, not {\"query\": none}."
```

Note the leading space inside the existing line (`"...filtering/pagination. "`) was extended to include a trailing space so the implicit concatenation joins cleanly without word-glueing.

### `src/robotina/agent/tools/start_workflow.py`

Appended to the existing `description = (...)` literal, after the existing `reply_context and household_id are injected automatically.` line (with `\n` line break to match the file's existing multi-line description style). Verbatim new segment:

```python
"reply_context and household_id are injected automatically.\n"
"Arguments are passed as JSON. Use JSON literals: null (not None or none), "
"true/false (not True/False). Strings must use double quotes. "
"Example: {\"recipe_query\": \"lentil soup\"}, not {'recipe_query': 'lentil soup'}."
```

Tailored the example to this tool's actual dict arg (`shared_context` typically holds `recipe_query`) so the contrast (`{"recipe_query": "lentil soup"}` vs `{'recipe_query': 'lentil soup'}`) is concrete and self-evident — JSON requires double-quoted strings; single-quoted Python-literal-style is wrong.
