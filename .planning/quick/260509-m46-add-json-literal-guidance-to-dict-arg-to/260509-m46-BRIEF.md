# Quick Task 260509-m46 — Detailed Brief

**Goal:** Add JSON-literal guidance to the `description=` field of every BaseTool whose arguments include dict-shaped fields, so the LLM knows the args are JSON and that `null`/`true`/`false` (not `None`/`True`/`False`) are required.

## Background (why)

A workflow recently died because the model emitted `{"query": none}` (Python literal) instead of `{"query": null}` (JSON literal) on a tool call to `household-manager-api`. Ollama's tool-call validator 500'd. We added retry as the failure floor (commit `f801814`). This task tackles the *root cause*: the tool description tells the model the arg shape (`dict | None`) but never says the dict serializes to JSON or that JSON literals must be used.

**Why the tool description is the right place:** LangChain/LangGraph injects each tool's `description=` into the agent's context every turn the tool is bound. It's universal coverage with zero overhead — the model sees it on every tool-call attempt, regardless of whether any skill file was read.

## Scope

Edit the `description=` fields on tools whose args include dict-typed fields:

1. **`src/robotina/agent/tools/household_manager_api.py`** — `body: dict | None`, `query: dict | None`. Add JSON-literal guidance.
2. **`src/robotina/agent/tools/start_workflow.py`** — `shared_context: dict`. Add JSON-literal guidance.

Tools to **skip** (no dict args, irrelevant to this fix):
- `queue.py` — text-only arg
- `read_skill.py` — string path arg
- `web_search.py` — string query arg

### Guidance to add

Each touched tool's description should include something like (English, concise — the model reads this verbatim):

> Arguments are passed as JSON. Use JSON literals: `null` (not `None` or `none`), `true`/`false` (not `True`/`False`). Strings must use double quotes. Example: `{"query": null}`, not `{"query": none}`.

The wording can be adapted per tool, but the three rules (`null` not `None`/`none`; `true`/`false` not `True`/`False`; double quotes) must be explicit.
