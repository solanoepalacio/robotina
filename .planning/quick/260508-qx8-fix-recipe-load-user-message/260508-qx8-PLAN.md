<objective>
The recipe-load agent receives only `f"Load recipe: {self.recipe.name}"` as its
user message — the structured `RecipeData` (ingredients, steps, times,
source_url) carried in `self.recipe` is silently dropped. As a result the agent
correctly concludes "the user just gave a recipe name" and refuses to proceed,
making zero tool calls. Production confirms this: a recent run produced a
"Receta agregada: unknown recipe" Telegram notification because the load step's
artifact had no real `recipe_name`.

Sibling inputs (`RecipeResearchInstructionsInput`, `RecipeResearchIngredientsInput`,
`RecipeResearchMetadataInput` at `task_types.py:130-185`) all dump their structured
fields via `json.dumps(...)`. `RecipeLoadInput` is the odd one out.

Fix: render the full `RecipeData` as JSON in `to_user_message()` so the agent
receives every field it needs (name, description, ingredients with
food_name/unit_name/quantity/note, steps with body/title, prep/cook/total times,
source_url, servings) and can run its name-resolution + `POST /api/recipes` flow.

Purpose: Restore the recipe-load step end-to-end so add-recipe actually creates
a recipe row in the household-manager system.

Output:
- Updated `src/robotina/queue/task_types.py` with the new
  `RecipeLoadInput.to_user_message()` body.
- New regression test in `tests/test_task_types.py` asserting all RecipeData
  fields appear in the rendered message.
</objective>
